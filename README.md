# Workout PWA

A minimal PWA for tracking strength and bodyweight progression. Open in
Safari on your iPhone, then **Share → Add to Home Screen**.

## Philosophy (read this before adding features)

Most workout apps over-abstract. They want to track every set, every rep,
every rest interval, every form note, every PR — and the result is a
spreadsheet that you have to fill out instead of an app that gets out of
your way. This app deliberately strips that down. Some core ideas the
codebase is built around:

### One tracked metric per exercise

Each exercise has exactly one metric the tier system actually progresses
on:

- Weighted exercises track **weight**.
- Bodyweight exercises track **reps**.

Everything else (sets, suggested rep counts on weighted exercises) is
**a suggestion**, not a target. The popover and details modal label them
explicitly as "suggested". If you're progressing on the tracked metric
and not being silly about form, the rest of your work is implicitly
keeping up — there's no need for the app to police it.

### Progression is monthly, not daily

The reason weight is shown as a *range* (e.g. `30–40 lb`) and not an
exact number is that day-to-day variance doesn't matter. What you lifted
today vs. yesterday vs. three weeks ago at the same tier is noise. What
matters is whether you've moved up a tier this month, which the chart in
the details modal makes obvious.

The history we save is enough to reconstruct that picture, but the UI
deliberately doesn't surface day-by-day numbers, because rewarding
yourself for "I did 47.5 instead of 45 today" trains the wrong habit.

### Levels and pips, not weights

Tier numbers are what the user climbs. Each weight upgrade fills one
**pip** inside a level; once all pips fill, the next upgrade rolls into
the next **level**. Pips give a felt sense of incremental progress,
levels are real milestones. The numbers are uniform within an exercise
(every tier is `weightStep` lb wide) so going from `30–40` to `40–50`
feels like the same kind of step every time.

`Lvl 0` is binary "I'm not yet able to do full sets at any weight". No
prescription, no chip row, just a check button. `Lvl 1` is the first
tier where the suggested sets/reps apply.

### Cross-exercise comparability matters

`Lvl 4` should mean roughly "advanced" no matter which exercise it's on.
Per-exercise tuning lives in `exercises.json` (`weightStart`,
`weightStep`, `pipsPerLevel`, `levels`, `snoozeDays`) so this stays
calibratable. If a new exercise can't reach a felt-advanced ceiling at
its current settings, retune the JSON, not the UI.

### Snooze keeps the home screen honest

Anything completed today (or within `snoozeDays`) drops into the
collapsed Snoozed card so the Available card always shows what's
*actually* up. The user shouldn't have to scroll past completed rows to
see what's next.

### Don't add metrics, don't add tracking

If a feature request is "track X per session", the answer is almost
always no. Surface what's already saved (history, levels, snooze) in
better ways instead. Examples that fit the philosophy:

- Better visualizations of progression (chart, muscle diagrams).
- Filters and reorderings that make the existing rows easier to act on.
- Settings to back up / restore the existing data shape.

Examples that *don't* fit:

- Per-set weight logging.
- Rest-timer enforcement.
- Heart-rate or RPE inputs.
- Anything that turns the green check button into a multi-step form.

### Purpose icons (the "tendon exception")

Some exercises aren't really about loading the muscle — tendon
conditioning, mobility, cardio, balance, skill work. Those carry an
optional `purpose` field that surfaces a small icon by the level pill,
as a reminder not to chase max load. Default `purpose: "muscle"` shows
no icon.

## Layout

- `index.html`, `styles.css`, `app.js` — the shell.
- `exercises.json` — the catalog. Add or tune exercises here, not in
  code. Each template carries `id`, `name`, `muscles`, `icon` (a key
  from the `ICONS` registry in `app.js`), the metric scaling
  (`weightStart`/`weightStep` or `repsStart`/`repsStep`), `pipsPerLevel`,
  `levels`, optional `snoozeDays`, `common`, `description`, `mistakes`,
  `purpose`, and the `bodyweight` flag for non-weighted exercises.
- `manifest.webmanifest` — PWA manifest.
- `service-worker.js` — caches the shell for offline launch. Bump
  `CACHE_VERSION` whenever any cached asset changes so installed clients
  pick up the update.
- `icons/` — generated by `scripts/make_icons.py`.

State is persisted in `localStorage` under a versioned key
(`workout-app:state:vN`). Migration flags live on the state object
itself (e.g. `levelsResetV8`) so a one-time reshape can be applied
without losing everything.

To regenerate the app icon: `python3 scripts/make_icons.py`.

## Run locally

A service worker requires `https://` *or* `http://localhost`. Plain HTTP
over LAN won't register the SW.

### Quick LAN test (no install)

```sh
python3 -m http.server 8000 --bind 0.0.0.0
```

Visit `http://<your-laptop-ip>:8000` from the phone. The app renders;
the SW won't register and "Add to Home Screen" won't behave like a real
PWA.

### HTTPS over LAN (for the iPhone install test)

```sh
# from this directory
python3 -m http.server 8000
# in another terminal
npx --yes localtunnel --port 8000
# or: cloudflared tunnel --url http://localhost:8000
```

Open the HTTPS URL in Safari on the iPhone, then **Share → Add to Home
Screen**.
